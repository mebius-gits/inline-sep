# 師園鹽酥雞・學號分單

Node.js + Express + SQLite 的團購登記網站，支援手機與桌面瀏覽器。學生只需填學號、選餐點；主揪在後台查看每個人吃什麼，產生可貼給店家的分裝備註。

## 啟動

需要 **Node.js 22.13 或以上版本**。使用 Node 內建 `node:sqlite`，不需要另裝資料庫服務或原生編譯工具。部分 Node 22 版本會顯示 SQLite experimental 提示，這不是啟動失敗。

```sh
npm install
npm start
```

- 點餐頁：<http://localhost:3100>
- 主揪後台：<http://localhost:3100/admin>
- 首次請在伺服器本機的後台設定至少 12 個字元的密碼。沒有預設密碼。設定後可在其他裝置用同一密碼登入。
- 開發時可用 `npm run dev`，修改伺服器程式後會自動重啟。

啟動時會建立 `data/orders.sqlite`，並匯入 39 項餐點。測試使用獨立暫存資料庫，不會寫入正式訂單。

## 手機與同學連線

伺服器預設監聽 `0.0.0.0:3100`。電腦與手機連上同一個 Wi-Fi 後，開啟終端列出的 `http://電腦區網IP:3100`。電腦需保持開機，Windows 防火牆需允許 Node.js 接受私人網路連線；學校 Wi-Fi 若隔離用戶裝置，需改用可互通的網路或部署到伺服器。

從區網網址開啟後台後，「複製點餐連結」即可取得可供同網路同學使用的網址。`localhost` 只代表目前這台裝置，不能直接分享給同學。

若需不同網路都可連線，部署到支援 Node.js 的主機或 VPS，使用 HTTPS 反向代理並保留可寫入的資料目錄。此專案沒有發布到公網；靜態網頁空間和不支援持久磁碟的執行環境不能直接保存此 SQLite 資料庫。

## 點餐與分單規則

- **每個學號、每團餐點金額最多 NT$150**，剛好 NT$150 可以送出；不是限制 150 人或 150 份。
- 前端即時計算預算，後端以資料庫的餐點價格重新計算，資料庫亦限制訂單金額。
- 學號為 3–20 位英數字或連字號，統一轉大寫，前導零會保留。
- 每團每個學號只能有一筆有效訂單。需要修改時由主揪取消原單，再讓該學號重新登記。
- 口味備註選填，最多 200 字、單行。未填時，分裝備註標記「照店家一般做法」。
- 網路中斷後重送同一筆資料會回傳原訂單，避免重複建立。
- NT$150 僅計算餐點，**不包含店家外送費**；本系統未提供付款功能。
- 本系統不驗證學籍或學號持有人，適用於信任的班級／團體。上線至開放網路時，如需防止冒用，應再接校務登入或邀請機制。

## 主揪操作

1. 從 `/admin` 登入，將點餐網址提供給同學。
2. 在「同學訂單」查看學號、餐點、口味、金額，可搜尋及下載 CSV。
3. 「餐點統計」彙整各品項數量與小計。
4. 收單完成後按「截止收單」，再到「分裝備註」複製文字或下載 TXT。
5. 主揪到店家原頁選餐，將備註貼入訂單，並向店家確認能否依學號分袋。
6. 下次訂購按「開新團購」；舊團自動截止且保留，點餐連結維持不變。

後台每 15 秒更新訂單，前台每 30 秒更新收單狀態；送出時仍會即時檢查。菜單可修改品名、分類、價格、上下架，也能新增品項。修改菜單不會更改已成立訂單的品名與價格。學生若持有舊價格，送出時會收到重新整理提示。

備註格式範例：

```text
【師園鹽酥雞・一起訂餐｜分裝備註】
共 2 袋，請依下列學號分開裝袋，袋外標示學號；不同學號請勿混裝。
1. 學號 B11200001：鹽酥雞 × 1、甜不辣 × 1；備註：小辣、不加蒜
2. 學號 B11200002：鹽酥雞咖哩飯 × 1；調味：照店家一般做法
```

這是獨立的團購登記網站，**不會自動送單到 inline 或店家**。店家原頁預設混裝，分裝文字是提出需求，並不代表店家已承諾分袋。

## 菜單與圖片來源

依使用者於 2026-11-20 提供的 inline 頁面 HTML 建置：咖哩飯 1 項、鹽酥雞類 19 項、串燒類 6 項、蔬菜類 8 項、點心類 5 項，共 39 項。圖片依該 HTML 的來源下載至 `public/assets`，執行時不依賴遠端圖片。

原頁的「調味料勾選」為 NT$0，但提供的 HTML 未含其彈窗選項，因此以不收費的口味文字備註承接，沒有臆造調味選項。選餐頁依原站的分類、圖片、價格及白底橘色樣式重建，並非原站程式的逐像素複製。未包含原站追蹤、付款或驗證腳本。

菜單初次匯入檔案在 `lib/menu.js`。後續請從後台維護，重啟不會覆蓋修改。

## 環境變數與部署

需要自訂時，將 `.env.example` 複製成 `.env` 後修改：

| 變數 | 預設值 | 用途 |
| --- | --- | --- |
| `PORT` | `3100` | HTTP 埠 |
| `HOST` | `0.0.0.0` | 監聽介面；只允許本機時改為 `127.0.0.1` |
| `DB_PATH` | `data/orders.sqlite` | SQLite 檔案位置，部署時指向持久磁碟 |
| `ADMIN_PASSWORD` | 不設定 | 僅在尚未設定後台密碼時使用，至少 12 字元；已有密碼後更改此值不會重設密碼 |
| `COOKIE_SECURE` | `false` | 對外 HTTPS 部署設為 `true`；本機 HTTP 保持 `false` |

一般部署流程：`npm ci --omit=dev`、設定環境變數和持久資料夾、執行 `npm start`，再由程序管理器保持運作。反向代理必須保留原始 `Host`，例如 nginx 的 `proxy_set_header Host $http_host;`。首次部署可用環境變數設定後台密碼，因為初次密碼設定頁只接受直接的本機連線。

以單一 Node 程序服務本團購。後台密碼使用 scrypt 雜湊，登入 session 保存於 SQLite，Cookie 設為 HttpOnly、SameSite=Strict。學生端無法讀取訂單名單或匯出資料；API 包含金額、格式、同源與基本速率檢查。CSV 防止公式注入並以文字保留學號。

備份時先停止伺服器，再複製整個 `data` 資料夾；若自訂 `DB_PATH`，請備份該檔案及其 SQLite 相關檔案。不要在伺服器運作時只複製主檔而忽略 WAL。還原時停機後放回原位置。

## 驗證

```sh
npm test
npm run test:browser
```

API 測試涵蓋：完整菜單、NT$150 上限、錯誤數量、偽造價格、併發重複學號、冪等重送、後台存取限制、分單統計、歷史價格、截止／重開、取消、歷史團購及 SQLite 重啟保存。

瀏覽器測試使用已安裝的 Chrome（可用 `BROWSER_CHANNEL=msedge` 改為 Edge），驗證桌面／390px 手機的點餐、確認、後台登入、備註下載、收單狀態、歷史團購、修改菜單與畫面不溢出。截圖寫入忽略追蹤的 `artifacts` 資料夾。
